# Security configuration and operations

Environment defaults are documented in `.env.example`. `ENVIRONMENT=production` requires a non-default signing secret, allowed origins and `SECURITY_RATE_BACKEND=postgres` (along with the existing production checks). Memory limits are for local single-worker tests only. Run migration 022 with migration-owner credentials; use `mshwar_backend` for requests.

Endpoint windows are 60 seconds, with independent endpoint/IP and signed-in user buckets. Auth: 20 anonymous / 60 authenticated; planner: 5 / 30; checkout: 20 / 60; catalogue/location/business search: 60 / 120; remaining: 60 / 240. Authenticated IP caps are three times the user limit so shared networks retain headroom. Existing password-reset safeguards also apply. Rejected requests return HTTP 429 plus `Retry-After` seconds and `X-RateLimit-Policy`; the web receives both via CORS.

AI reservations are USD micros, default 100,000 per planner POST and 5,000,000 per user per UTC day. They commit before provider work, survive failures, and are deliberately not refunded. This bounds request-derived cost only while each request’s worst-case cost, including retries, is <= its reservation. The current LLM adapter remains stub-only. Update the bound and tests when introducing a paid adapter. `GET /api/v1/admin/security-metrics` exposes process counters for allowed/denied endpoint requests, AI and upload limits; scrape each replica into monitoring. Persistent counters enforce limits; process metrics reset on restart.

Uploads: 5 MiB each, 30 uploads/org/hour, 100 MiB/org/UTC day by default. PNG/JPEG/WebP listing images and PDF verification documents require matching signatures and allowed purpose. Signed downloads expire in at most 300 seconds; URLs are bearer credentials. ImageKit uses both `IMAGEKIT_API_KEY` (private server key) and `IMAGEKIT_URL`; with keys unset it writes to `PRIVATE_STORAGE_DIR`. Mount persistent private storage outside the web root for a real pilot. Configure ImageKit to reject unsigned private-file transformations before enabling it.

Sentry is off with an empty `SENTRY_DSN`. When configured the API installs `before_send`/breadcrumb scrubbing, disables local-variable capture, default PII and tracing. The web exports `sentryBeforeSend` for a future SDK integration; no browser Sentry/PostHog SDK is loaded by this change. Any browser analytics integration must consult `analyticsAllowed()` before loading and react to `mshwar:consent` revocation. Never send secrets as telemetry, even if a scrubber is installed.

`X-Request-ID` is a validated/generated UUID at the web/API boundary and returned on API responses. Browser API helpers send a fresh opaque request ID; server logs attach the matching ID. Values are identifiers only and grant no access. Do not add user IDs, email addresses, raw URLs or payment IDs to correlation labels.

Audit search is `/admin/audit`; every search requires the existing platform-admin access policy. Search can filter action (`INSERT`/`UPDATE`/`DELETE` and existing operational actions), actor UUID, target table, time range and reason/target query. No edit/delete UI or API exists. The app role cannot UPDATE/DELETE/TRUNCATE records; only controlled database-owner maintenance can manage legal retention under an approved procedure.
