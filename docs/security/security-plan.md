# Security plan

Status: proposed · Written: 30 September 2026 · Builds on: [review-2026-09.md](review-2026-09.md) (SR-01 to SR-21), [threat-model.md](threat-model.md)

Mshwar already has a strong base: one access policy per route checked at start-up, row-level security under a
restricted database role, argon2 password hashing, rate limits in Redis, a cross-site request guard, an
append-only audit log, a log and Sentry scrubber, upload structure checks, two-step sign-in for admins, and
CI scanners (gitleaks, ruff `S`, pip-audit, pnpm audit, Semgrep, Trivy). This plan does not redo that work. It
lists every remaining gap found by reading the code, the compose files and the staging box, and every
standing practice needed to keep the product safe as it grows.

## How to read this

- **ID**: `SEC-NN`, so work items, commits and tests can refer to one line.
- **Where**: _Code_ (a pull request), _Server_ (the staging or production box), _GitHub_ (repository
  settings), _You_ (a decision or an outside party).
- **Priority**:
  - **P0**: this week. Real exposure today, small change.
  - **P1**: before public launch.
  - **P2**: hardening after launch, within three months.
  - **P3**: standing practice, runs forever.
- **Done when**: the check that proves it. Code items always end in an automated test that runs on every
  pull request, so a fix cannot silently regress.

## 1. Server and hosting

The staging box is Ubuntu 24.04 on Oracle Cloud (arm64). Caddy is the only published service (80/443);
Postgres, Redis, the API and the web app are internal to the compose network. `ufw` allows 22, 80 and 443.

| ID     | Pri | Where  | What and why                                                                                                                                                                                                                                                                                                                     | Done when                                                                                                                    |

| SEC-02 | P0  | Server | **Automatic security updates.** Install `unattended-upgrades`, security origin only, with an automatic reboot at 04:00 Beirut time when required.                                                                                                                                                                                | `systemctl status unattended-upgrades` is active; `/etc/apt/apt.conf.d/50unattended-upgrades` has `Automatic-Reboot "true"`. |

## 3. Accounts, sign-in and sessions

What exists: argon2id hashing; sign-in limited per IP and per email; reset tokens stored hashed, 30-minute expiry,
single use, and using one signs out every session; admin TOTP; `HttpOnly`, `SameSite=Lax` session cookie with
`Secure` when deployed; 7-day sliding session.

| ID     | Pri | Where | What and why                                                                                                                                                                                                                                                                                           | Done when                                                                                               |
| ------ | --- | ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------- |
| SEC-21 | P1  | Code  | **`__Host-` cookie prefix.** Rename `mshwar_session` to `__Host-mshwar_session` when deployed. The browser then refuses the cookie unless it is `Secure`, has `Path=/` and has no `Domain`, so a subdomain cannot set or overwrite it. Accept the old name for one session lifetime during the switch. | Test: the deployed cookie name starts with `__Host-` and has no `Domain`.                               |
| SEC-22 | P1  | Code  | **Change password while signed in.** Today a user can only reset by email. Add `POST /auth/password` that needs the current password, rehashes, signs out every other session, and emails "your password was changed".                                                                                 | Test: a wrong current password gets 403; after a change, other sessions get 401 and an email is queued. |
| SEC-23 | P1  | Code  | **Refuse known-breached and common passwords.** Minimum length is already 10. Add an offline list of the 100,000 most common leaked passwords (no outside call) checked at sign-up, reset and change.                                                                                                  | Test: `Password123!` is refused with a clear message.                                                   |
| SEC-24 | P1  | Code  | **Sessions page and "sign out everywhere".** List active sessions (device, approximate place from the IP's country, last seen) with a button to end one or all.                                                                                                                                        | Test: ending a session makes its cookie get 401.                                                        |
| SEC-25 | P1  | Code  | **Email change needs confirmation.** Changing the account email sends a link to the new address and a notice with a "this wasn't me" link to the old one; the change only happens after the link is used.                                                                                              | Test: the email doesn't change until the token is used; the old address gets the notice.                |
| SEC-26 | P2  | Code  | **Two-step sign-in for guides, drivers and businesses.** Reuse the admin TOTP code. Offer it to everyone; require it for accounts that receive money or hold other people's phone numbers (guides, drivers, business owners).                                                                          | Test: a guide with TOTP enabled is asked for a code; a wrong code is refused and rate limited.          |
| SEC-27 | P2  | Code  | **Passkeys (WebAuthn).** Add passkeys as a sign-in and second-step option; they cannot be phished.                                                                                                                                                                                                     | Playwright test with a virtual authenticator signs in.                                                  |
| SEC-28 | P2  | Code  | **New-device sign-in notice.** When a sign-in comes from a new device and country, email the user with a link to the sessions page (SEC-24).                                                                                                                                                           | Test: a sign-in with a new user-agent and IP queues the email.                                          |

What exists: React escapes output by default; the only `dangerouslySetInnerHTML` is JSON-LD (escaped); `safeNextPath`
guards redirect targets; 422 bodies never echo values; SQL is always parameterised (raw SQL through `fetch_json`
with bound values).

| ID     | Pri | Where | What and why                                                                                                                                                                                                                                                       | Done when                                                                                            |
| ------ | --- | ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------- |

Add `'strict-dynamic'`. Keep `style-src 'unsafe-inline'` only if Tailwind requires it.          | E2E test: the page loads with no CSP violation; an injected `<script>` without the nonce is blocked. |
| SEC-36 | P1  | Code  | **Narrow `img-src` (SR-21).** Allow `'self'`, `data:`, `blob:`, the ImageKit endpoint, OpenStreetMap tiles through `/map-tiles` and Wikimedia (catalogue photos), and nothing else.                                                                                | The CSP header lists those hosts; the catalogue and tour pages show every image.                     |

| SEC-45 | P1  | Code   | **Encrypt stored third-party secrets.** A guide's connected calendar address (`guide_external_calendars.url`) is a secret that grants read access to their calendar, stored in plain text. | SEC-46 | P1  | Code   | **Redis password.** Redis has no password and relies on the compose network.
